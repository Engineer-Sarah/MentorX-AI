The app follows a clear three-layer layout built on Streamlit's multi-page convention: `app.py` is the entry point that initializes the SQLite database (`mentorx.db`) via `src/database.py`, sets up page config, and manages per-session state in `st.session_state`; `pages/1_Career_Assessment.py` through `7_Career_Dashboard.py` are individual Streamlit pages that each import shared logic from `src/`. The `src/` package provides domain services — `assessment_engine.py` scores quiz answers against dimension metadata loaded from `data/assessment_questions.json`, `gemini_service.py` centralizes all Google Gemini API calls (model `gemini-2.0-flash`) behind structured JSON prompts with `_safe_call` fallbacks, `resume_parser.py` handles resume text, and `utils.py` holds helpers. `src/database.py` defines the SQLite schema (sessions, assessments, recommendations, skill_analyses, roadmaps, resumes, interviews) and exposes per-feature CRUD functions; every feature page persists results through these functions and advances the session's `current_step`. Data assets live under `data/` (assessment questions, career database), configuration under `.env` (loaded via `python-dotenv` for `GOOGLE_API_KEY`), and Streamlit UI tweaks under `.streamlit/config.toml`. Dependency direction is strictly one-way: pages → src services → SQLite + Gemini; there is no cross-import between pages.
